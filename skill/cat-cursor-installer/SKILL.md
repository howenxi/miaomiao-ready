# 喵喵就位

## 安装后的欢迎引导

用户刚安装此 skill，或询问如何开始时，直接给出简短的中文使用引导，让用户知道下一步上传什么、上传后怎样选择。安装本身由宿主或安装代理执行，本 skill 被读取后输出这段引导；不要宣称已在宿主实现自动弹窗或消息触发。

欢迎引导可采用以下内容，并结合用户已经提供的信息删减重复问题。

> 喵喵就位准备好了！上传你的小猫照片，我会先设计造型，等你确认后制作一键安装包。
>
> 请上传一张清晰正脸照，尽量自然光、无遮挡、不用滤镜，让眼睛和脸部花纹看得清。有全身、侧身或尾巴照片也可以一起发，方便还原毛色和体型。多只猫可以分组上传，并告诉我名字；同一只猫的多张照片请放在一组。照片不足时也可以先上传现有照片。
>
> 上传后，我会先确认每只猫的特征，再让你选择鼠标类型。你可以全选，也可以只选其中几种，并给每种类型指定一只猫。告诉我电脑是 Windows 10/11 还是 Mac，随后我们确认预览，再生成适用的安装文件。

若当前是在为用户安装或更新此 skill，把上述引导放进安装完成的回复，附上下一步上传照片的提示。若只是在维护、打包或分享 skill 文件，在交付中说明对方安装后可用照片开始，勿把当前用户当成第一次使用。

## 上传后的分类与角色分配

收到照片后先实际查看，不立即一次性生成八种图。按用户的猫名归组，未命名时用“小猫A”“小猫B”等临时称呼。同一只猫不同角度的照片合并为同一个角色。给出每组的关键特征，让用户能发现归组错误。

随后列出八个可选类型，用名称和用途帮助用户选择：正常选择（普通移动和点选）、文字输入（输入框与选字）、链接点击（链接或手形操作）、不可用（禁止操作）、忙碌中（等待处理）、移动画布（拖动或移动）、左右调整（横向改大小）、上下调整（纵向改大小）。

提供简单的回复示例：“八种全选，都用团团”；或“团团用正常选择、文字输入，圆圆用链接点击、忙碌中，其他不要”。用户只说“全选”时，一只猫直接分配全部，多只猫且未指定对应关系时先询问分配，也可以提出分配建议供用户确认。用户已明确指定的内容直接采用。

角色归组和类型选择完成后，简短汇总系统、选中类型及每项对应的小猫，再进入设计预览。最终流程保持“照片 → 选择与分配 → 确认预览 → 生成一键安装包”，无需用户再导入工作台。

在支持文件操作和图像生成的 Codex 环境中，把用户的小猫照片制作成鼠标安装包。图片生成通过当前环境可用的图像工具完成，工具可用时直接调用。模型版本只能按工具实际提供的信息描述。

## 收集配置

先利用已有对话确定目标系统。Windows 10/11 使用随附安装器模板。Mac 电脑使用 macOS 路线，阅读 [macos.md](references/macos.md)。用户说 iOS 时确认是否指 Mac。

支持一次上传多只猫。为每只猫编号并记录可辨识的毛色、脸部花纹、眼睛颜色，照片须实际查看。把以下八个类型列给用户选取，并建立逐类型的小猫映射。用户已说明的选择直接采用。未指定类型时可建议八种全选；只有一只猫时可直接分配，多只猫未分配时按前面的分类引导确认，避免擅自全部使用第一只。

| ID | 类型 | 姿势与点击热点 |
|---|---|---|
| normal | 正常选择 | 抱住箭头，热点在左上箭尖 |
| text | 文字输入 | 紧凑细长 I 形，右下角放小猫头和爪子，热点在 I 形中心 |
| link | 链接点击 | 向点击方向伸爪，热点在爪尖 |
| unavailable | 不可用 | 扶住禁止符号，热点在符号中心 |
| busy | 忙碌中 | 蜷睡配加载弧，热点在主体中心 |
| move | 移动画布 | 伸爪或抱移动符号，热点在指示中心 |
| horizontal | 左右调整 | 猫趴在横向双箭头上，热点在箭头中点 |
| vertical | 上下调整 | 猫扶竖向双箭头，热点在箭头中点 |

忙碌状态默认静态 CUR。用户要求循环动画时另做 ANI。移动画布对应 Windows 的 SizeAll，软件自己的抓手可能不随系统主题变化。

## 生成设计

### 根据真实照片保留每只猫的独特性

以本次用户上传的照片作为角色设计依据。逐只观察并记录能区分身份的特征，包括脸型与胖瘦、耳朵大小和形状、眼睛颜色与眼型、鼻子颜色、毛长、额头与两侧脸颊花纹、白胸白爪范围、身体色块和尾巴形态。尤其保留不对称花纹与明显的个体特征，左右方向以参考照片为准。看不清的特征结合其他已上传照片判断，只有影响辨识且无法确定时再询问用户。

绘制前给每只猫建立简短的特征描述，并把该猫的真实参考图和特征描述一起用于生成。后续状态优先复用已确认的角色参考，持续核对花纹位置、脸型、眼睛和体态。多只猫共同出现时，确保各状态对应用户指定的小猫。

不同小猫的区别应体现在轮廓、面部比例、花纹与神态中。画风和线条可以统一，角色需要保留各自特色。避免套用同一张圆脸、同一种眼型和体型，再仅换毛色，也不要把本 skill 以前生成的银白猫或三花猫当成所有用户的固定模板。

卡通化时简化细碎毛发与纹理，保留最有辨识度的形状和色块。以照片中可见的自然神态作为表情依据，姿势围绕各鼠标功能设计。小尺寸可读性与真实特征发生冲突时，先保留该猫最显著的两三项识别特征，再调整细节。

预览验收需把设计与各自的原始照片并排核对：是否能看出是哪只猫、是否误改标志花纹、不同猫是否仍有明显差别。用户认为“不像”或“太模板化”时，回到真实照片调整角色特征，再继续生成状态和安装包。

按当前可用的图像生成工具规范操作。用户指定的图像工具可用时优先使用。缺少图像工具时明确缺失条件，保留配置和已完成内容，不把普通照片改扩展名充作设计。

保持每只猫的身份一致，采用适合小尺寸的粗描边卡通。可以先生成预览排版用于看整体风格。生成安装用素材时，每种类型独立输出透明 PNG，图中只含猫及功能符号。清除卡片、文字、阴影、热点标记和外部光晕。通过图像工具修正画面，程序仅用于裁切、缩放和文件编码。

文字输入优先保证选字和插入定位清楚。使用紧凑 I 形，小猫仅露头和两只前爪，放在右下角。I 形总高度约为猫头高度的两倍，中心附近留透明空间，猫脸和身体避开文字定位点。避免全身猫抱住粗 I 形，也避免把 I 形拉成细长杆。预览确认后，再从实际图像测量 I 形上下端的中点作为热点，检查 32/48 像素大小下的猫头识别和遮挡。

另外生成一张朝右奔跑的透明小猫，供安装进度使用。头朝右、尾巴向左。默认使用正常选择所分配的小猫，正常选择未选时使用首个选中类型的小猫。单张图配位移起伏属于姿势动画，需要逐帧奔跑时生成连续帧。

查看每张实际 PNG，确定透明区域和完整轮廓，在原图坐标中选定热点。实际指针预览需检查 32、48、64 像素下的可辨识性。与用户约定的预览确认阶段继续遵守，已授权直接生成安装包时完成打包，避免重复询问。

## Windows 打包

阅读 [windows.md](references/windows.md)，建立任务输出目录及配置 JSON。执行随附 `scripts/build-windows.ps1`。它只嵌入本次用户提供的素材，为选中类型创建 32/48/64/96 像素 CUR，编译带高清适配声明的原生窗口程序，输出安装与恢复程序和 ZIP。使用环境中现有的 PowerShell、.NET Framework 编译器；缺失时查找可用的 Windows 编译环境，清楚说明真正缺失的依赖。

安装窗口使用“喵喵就位”，小猫沿真实步骤进度向右移动，完成后同窗显示“已完成，请试用鼠标效果”，仅展示所选类型。整体采用奶油底色与焦糖棕主题，顶部使用加大的猫咪图标和“喵喵就位”品牌栏，可拖动窗口。场景卡片使用暖色描边圆角，主按钮焦糖棕、次按钮暖棕描边，输入框采用一致的圆角及暖色悬停反馈。输入提示在鼠标移入或聚焦时隐藏，移出且未输入时恢复，用户输入保留。

安装仅设置当前用户。首次备份持续保留，版本化素材目录防止新主题误用旧猫图。恢复入口还原首次设置。失败尝试恢复并清楚显示错误。刷新调用使用 Unicode `SystemParametersInfoW(SPI_SETCURSORS, 0, NULL, 0)`，最后参数必须为零。

## 验证与交付

运行生成 EXE 的 `--self-test <独立测试目录>`，验证 CUR 能被 Windows 读取、输入提示行为、加载及完成界面。检查常用缩放比例，包含系统实际比例。自检仅生成文件和窗口预览。

安装/恢复验证会实际改变当前桌面指针，只在已有授权和正常桌面环境中进行，独立目录备份，务必在结束时恢复并核对原值。必要时执行 `--integration-test <新的独立目录>`。这个模式应用选中类型，再恢复并对比备份。用户未要求在当前设备安装时，只交付安装包，说明已验证范围。

交付 ZIP 的实际文件链接、双击入口、恢复方式和未验证项。生成程序可能没有数字签名，应如实说明系统提示。不要宣称运行时已验证却仅做了编译。

随 skill 分享的内容只含通用流程、转换脚本和安装器源码。其他用户的照片、既有角色图、备份和安装结果均属于每次任务的输出。

视觉还原时，以用户确认的原型作为验收依据。品牌头像单独生成完整坐姿透明图，配置 brand 路径，勿从指针图裁切。顶部格纹、弧线和爪印、卡片竖分隔线、加粗标题、较大的角色图及底部分隔线均由模板实现。交付前展示实际程序截图并对照原型，说明仍有差异的项目。

文字输入的实际显示高度须同时检查导出比例。当前主题对文字输入使用 contentScale=0.65，使32px画布中图案高度约20px，48px约30px；仅改变原图比例会被自动裁切放大抵消。将CUR真实像素叠到文字上检查后交付。

整套大小一致性：同一主题默认使用一致的contentScale；当前八种均为0.65，各尺寸输出图案最长边一致。预览以去除透明边后的实际轮廓统一最长边64逻辑像素，保留纵横比，不因原图留白导致一款过大或过小。用户明确要求单项例外时再分别调整。
