## 从鼠标主题到安装程序

用户参考一套八状态猫咪指针，希望用自己的猫制作主题。原理是为 Windows 各指针角色配置 CUR，静态图设置点击热点，多帧动画可用 ANI。最终八种状态为正常选择、文字输入、链接点击、不可用、忙碌中、移动画布、左右调整、上下调整。

第一只为银白猫，保留圆脸、银灰额纹、浅绿眼睛。先生成抱箭头原画，再导出 CUR。随后补齐八状态。用户再上传三花猫照片，指定文字输入、链接点击、不可用和忙碌中改用三花猫，其他四种继续用银白猫。

Windows 角色映射为 Arrow、IBeam、Hand、No、Wait、SizeAll、SizeWE、SizeNS。移动画布映射到 SizeAll，一些软件自己的抓手不跟随系统主题。忙碌中目前采用静态 CUR。

## 安装体验的确定

用户要求双击运行、自动安装，不希望闪出命令窗口。安装对象是当前 Windows 用户，采用图形 EXE。首次保存原鼠标设置，重复安装保留原始备份，另有恢复入口。素材放入用户 LocalAppData 的 MiaoMiaoReady 下，下载目录移动后仍可使用。程序未签名，Windows 自身仍可能显示安全提示。

用户提出加载弹窗上有进度条、小猫在上方跑，结束后同一窗口显示“已完成，请试用鼠标效果”，并展示八种场景。名称最终选为“喵喵就位”。进度根据实际步骤推进。动画目前为单张奔跑姿势向右移动并起伏，四肢没有逐帧运动。

## 已遇问题及处理

### 文件图标只剩小点

首版 EXE 图标在文件列表的小尺寸下异常。重新生成多尺寸 ICO，并重新编译。后续系统缓存旧图标时，使用新目录查看。

### 安装和恢复均报 Windows 未能刷新鼠标方案

安装器写入设置后，刷新参数传入了 3，实际桌面中复现失败。改为 Unicode SystemParametersInfoW，SPI_SETCURSORS 为 0x57，最后参数使用 0。正常桌面验证成功，完成过应用八种指针、刷新、恢复原值及数据类型核对。注意受限执行环境可能返回访问拒绝，不能据此单独判断用户正常桌面是否失败。

### 文字和图片发糊

程序缺少高分屏声明，Windows 整体放大产生模糊。加入系统 DPI 感知 manifest，按 DPI 调整布局。图片按实际显示尺寸高质量缩放后缓存，动画中直接绘制缓存图，加双缓冲。检查过 100%、125%、150% 模拟比例。跨不同缩放显示器时建议重启窗口；没有完成所有显示器环境的真机验证。

### 按钮与输入框不协调、提示文字不会消失

先按 Ant Design 风格原生绘制圆角按钮与输入框，加入悬停和焦点状态。原来输入框默认 Text 被当成输入内容，改为真正占位提示。鼠标移入或获得焦点时隐藏，移出且未输入时恢复；已输入文字保留。相应行为自检已通过。后来按钮随整体风格改为焦糖色。

### 加载猫方向反了

最初复用移动画布图片，猫朝左上而进度向右。另行生成朝右奔跑的银白猫透明图，并替换加载资源。生成图出现外部光晕时再次调用图像工具清理。保留最终奔跑素材。

用户最初说 iOS，随后澄清指苹果 Mac 电脑 macOS。Windows 的 EXE 和 CUR 安装方式不能直接用于 Mac。skill 指引检查 Mousecape 及对应系统版本兼容性，交付时明确依赖。当前没有完成可直接分发、经真机验证的 Mac 自动安装器。

## 纠正未解决的大小差异（2026-11-19）
用户确认运行的是最新版，问题仍与视频一致。复现发现卡片内试用正确，卡片外系统指针更大。对照读取证实：配置32、实时48；仅写注册表与SPI_SETCURSORS无法取消实时倍率。通过0x2029设置实时32、0x2028确认后，屏幕大小回归，24个系统副本与CUR像素严格一致。撤销上一轮“系统边缘处理允许2px误差”的判断与宽松验收。旧备份补齐大小设置及实时值，恢复流程验证48→32→48成功，三档实际点击应用核对通过。源码、模板、正式包和Skill统一更新。
